# SocialNetwork

Социальная сеть с профилями, записями, музыкой, видео, новостями, друзьями и диалогами в реальном времени.

Клиент — React 18 (Feature-Sliced Design).  
Сервер — Node.js, Express 5, Sequelize и PostgreSQL.

Клиент: [http://localhost:3000](http://localhost:3000)  
API и WebSocket: [http://localhost:5000](http://localhost:5000)

## Возможности

- **Вход и сессия.** JWT с ротацией, refresh-токен в httpOnly cookie, детекция повторного использования, автоматическое обновление в Axios, синхронизация между вкладками.
- **Диалоги.** Сообщения по HTTP и уведомления по WebSocket. Соединение авторизуется JWT и проверяется по серверной сессии.
- **Медиа.** Двухэтапная загрузка: временное хранение, затем публикация. Для видео — генерация превью и обложки через FFmpeg. Незакреплённые файлы очищаются фоновой задачей.
- **Лента.** Счётчики комментариев и лайков считаются в БД подзапросами; массивы в ответ не передаются — размер ответа не растёт с популярностью записи.
- **Новости.** Сбор RSS, разбор через Gemini с проверкой схемы Zod, публикация от имени бота. Повторы отсекаются по `source + externalId`.
- **Музыка и видео.** Загрузка, обложки и превью, личные библиотеки и избранное.
- **Приватность.** Записи, видео и новости видны владельцу, всем или только друзьям автора.
- **Погода.** Город и прогноз кэшируются в Redis.
- **Тема.** Светлая, тёмная или системная.

## Безопасность

- **JWT и refresh.** Access-токен короткоживущий; refresh — в httpOnly cookie с `SameSite=Lax`, ротация и отзыв, детекция повторного использования.
- **WebSocket.** Аутентификация по JWT с проверкой серверной сессии, ограничение origin, размера сообщения и числа соединений на пользователя.
- **HTTP.** `helmet` (CSP, HSTS, nosniff, CORP для `/uploads`), `express-rate-limit` на login/register/refresh, `trust proxy` для корректного IP за reverse proxy.
- **Cron.** Автоматизация новостей захватывает распределённую блокировку в Redis (`SET NX EX` + атомарный release через Lua), чтобы избежать дублей при нескольких инстансах.
- **Graceful shutdown.** На SIGTERM/SIGINT сервер корректно закрывает WebSocket, HTTP, PostgreSQL и Redis в нужном порядке.

## Запуск

Два терминала: сервер и клиент. PostgreSQL и Redis поднимаются через Docker.

### 1. Инфраструктура

В корне репозитория:

```bash
cp .env.example .env
```

Заполните `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` и `REDIS_PASSWORD`. Затем:

```bash
docker compose up -d
```

PostgreSQL слушает порт `5432`, Redis — `6379`.

### 2. Сервер

```bash
cd server
yarn install
cp .env.example .env
```

В `server/.env` задайте как минимум:

- `NODE_ENV=development`
- `PORT=5000`
- `CLIENT_URL=http://localhost:3000`
- `JWT_SECRET` и `JWT_EXPIRES_IN`
- те же данные PostgreSQL и Redis, что в корневом `.env`
- `DB_URL` в формате `postgres://USER:PASS@localhost:5432/DB_NAME`

`GEMINI_API_KEY` нужен только для автоматических новостей. Без ключа остальное приложение работает.

Создайте базу, примените миграции и наполнители:

```bash
yarn dev:db
yarn dev
```

Сервер слушает `http://localhost:5000`.

### 3. Клиент

```bash
cd client
yarn install
yarn start
```

Адреса API уже заданы в `client/.env.development`:

```env
REACT_APP_API_URL=http://localhost:5000/api
REACT_APP_WS_URL=ws://localhost:5000
```

Откройте [http://localhost:3000](http://localhost:3000).

## Скрипты

**Сервер** (`server/`)

| Команда           | Назначение                                          |
| ----------------- | --------------------------------------------------- |
| `yarn dev`        | Запуск с nodemon                                    |
| `yarn start`      | Обычный запуск                                      |
| `yarn dev:db`     | Пересоздать базу разработки, миграции и наполнители |
| `yarn test:db`    | Пересоздать тестовую базу `socialnet_test`          |
| `yarn test`       | Все серверные тесты                                 |
| `yarn test:watch` | Тесты в режиме наблюдения                           |

**Клиент** (`client/`)

| Команда      | Назначение                  |
| ------------ | --------------------------- |
| `yarn start` | Режим разработки, порт 3000 |
| `yarn test`  | Тесты React                 |
| `yarn build` | Сборка для публикации       |

Тестовая база сервера должна называться `socialnet_test`. Интеграционные тесты в другой базе не запускаются.

Покрытие — сервер. Интеграционные тесты (на реальной БД): регистрация, вход, refresh, отзыв и повторное использование токенов, приватность постов и чужих библиотек, загрузка/публикация/очистка медиа, commentsCount и likesCount без загрузки массивов, редактирование сообщений и комментариев, WebSocket-авторизация, distributed lock в Redis. Unit-тесты: cookie, fromPublicUrl, online-status, Redis-лок.

Покрытие — клиент. Обновление JWT в Axios, гонки запросов, слайс и действия авторизации, синхронизация вкладок, межвкладочный refresh, WebSocket.

## Фоновые задачи

- Ежедневно (20:30). Очистка временных медиа, сиротских файлов, удалённых сообщений, истёкших сессий и старых новостей.

- Раз в час. Сбор RSS и публикация новостей через Gemini (если задан GEMINI_API_KEY). Запуск защищён распределённой блокировкой в Redis: при нескольких экземплярах сервера задача выполняется ровно на одном.

## Известные ограничения

- При ротации JWT WebSocket закрывается и открывается заново (около 15 минут). Непрочитанные сообщения подгружаются при следующем открытии диалога.

- Новости старше 30 дней архивируются и остаются в поиске. Их файлы фоновая очистка не удаляет.

- Автоматизация новостей защищена распределённой блокировкой в Redis. Короткие фоновые задачи (очистка, архивация, чистка сессий) пока защищены только от параллельного запуска внутри одного процесса.

- Файлы в `/uploads` раздаются статически и доступны по прямой ссылке без авторизации. Имена — UUID, угадать нельзя, но уже известная ссылка не отзывается. Приватность сущностей обеспечивается на уровне API (проверка видимости при чтении), а не на уровне файла. Для полной защиты приватных медиа потребуется подписанные ссылки с TTL.
